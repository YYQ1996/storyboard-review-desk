## 人工验证

1. 通过本地服务打开审核台。
2. 导入两镜头标准格式脚本并创建第 1 批。
3. 点击“创建 Codex 任务指令”，服务生成独立运行令牌。
4. 调用 Codex 内置图片生成能力生成一张 2 × 1 宫格图。
5. 通过已安装插件的 MCP 服务提交图片、完整脚本和布局。
6. 页面在下一次轮询中自动出现 v1。
7. 启动全新临时 Codex 任务，确认插件 Skill 与 MCP 工具均可发现并读取该版本。

## 已知限制

- 本节点使用的测试批次没有参考资产；带人物图和场景图的完整输入将在 M1 验收。
- 新 Codex 任务首次连接时 WebSocket 多次超时，随后自动降级到 HTTPS 并成功完成工具调用；当前不影响本地 MCP 功能。
- M0 验证的是人工创建新 Codex 任务的第一版路径，不包含 App Server 一键建任务。
- 同一批次返修复用任务时，历史图片仍可能存在于对话历史中；工具不会主动返回或上传历史宫格图。

## 遗留风险

- 需要验证多张人物/场景资产路径在真实生图任务中的可读性和引用顺序。
- 需要补齐本地服务重启恢复、旧 `localStorage` 迁移和历史版本只读的端到端验证。
- 个人插件当前引用本机项目绝对路径，只适用于本机开发；公共发布前必须改为可移植打包。
