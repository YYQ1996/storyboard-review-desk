# 分镜审核台 · 双平台真机验收矩阵（v0.1.12）

> 当前状态：矩阵与证据口径已建立；Windows 干净电脑和 macOS 真机证据尚未在本节点收齐，因此 M2 不得标记“已通过”。

## 1. 验收原则

- “源码测试通过”“安装包结构正确”和“真实干净电脑跑通”是三类不同证据，不能相互替代。
- Windows 与 macOS 必须分别完成整条链路；不能用一端结果推定另一端。
- 每次真机验收记录设备、系统、芯片、Codex 版本、安装包 SHA256、产品版本和时间。
- 首版生成与返修必须调用真实 Codex 内置图片生成并自动回填；演示数据、手工复制图片或模拟接口不算通过。
- 发现问题时保留截图、`install-log.txt`、导出的操作记录、运行 ID 和版本 ID。日志中涉及创作内容或本地路径时，不公开上传。

## 4. 当前已有的非真机证据

以下证据用于降低风险，但不把上表改为“通过”：

- Node 自动测试覆盖脚本解析、数据迁移、资产校验、14 项资产索引板、批次隔离、镜号归一、返修脚本、幂等回填、品牌和输入焦点。
- Windows 安装器隔离目录回归覆盖 CRLF 入口、显式用户配置目录、无 PATH 的 App 组件发现、失败窗口停留和重复启动检查。
- macOS 静态/结构测试覆盖 LF 入口、双架构运行环境、官方 CLI 安装兜底和重复启动预检。
- `v0.1.12` Release 的两个 ZIP 与本地 SHA256 一致。

## 6. M2 放行规则

- Windows x64 至少一台干净电脑完成 DP-01～DP-15。
- macOS 至少一台 Apple Silicon 真机完成 DP-01～DP-15。
- Intel macOS 若暂时没有设备，可单独保留“阻塞”，但发布页必须明确只取得结构验证；若继续宣称 Intel 已正式支持，则发布前仍需补齐真机证据。
- P0/P1 失败清零；P2 限制必须写入里程碑记录和使用说明。
- 证据收齐后新增 M2 补充验收记录，不回写或覆盖 M1 历史记录。
