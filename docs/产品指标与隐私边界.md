# 分镜审核台 · 产品指标与隐私边界

> M2 只定义口径，不实现埋点、账号、云同步或上传。任何观测能力必须在 M2.1 单独开发和验收。

## 1. 观测目标

未来观测只回答四类产品问题：

1. 学员能否完成下载、安装、启动和插件识别。
2. 学员从导入脚本到第一次成功回填，主要流失在哪里。
3. 生成、返修、回填和导出是否稳定，失败属于哪一类。
4. 新版本升级是否成功，是否影响本地核心功能。

它不用于收集用户创作内容、训练素材、用户画像或跨产品广告追踪。

## 2. 核心漏斗与指标

### 2.1 建议事件

| 事件 | 成功判定 | 允许的最小附加字段 |
| --- | --- | --- |
| `install_attempted` | 安装器开始 | appVersion、platform、arch、installMode |
| `install_succeeded` | 插件安装和登记完成 | appVersion、platform、arch、durationBucket |
| `launch_succeeded` | 健康检查返回当前版本 | appVersion、platform、arch |
| `plugin_context_read` | 插件成功读取一次批次上下文 | appVersion、mode、assetCountBucket、shotCountBucket |
| `generation_started` | 运行进入 generating | appVersion、mode、referenceMode、shotCountBucket |
| `version_submitted` | 新版本创建且回填成功 | appVersion、mode、durationBucket |
| `batch_passed` | 用户手动通过批次 | appVersion、revisionCountBucket |
| `final_exported` | 终版脚本成功导出 | appVersion、batchCountBucket、shotCountBucket |
| `operation_failed` | 允许列表内的步骤失败 | appVersion、stage、errorCode |
| `upgrade_succeeded` | 新版启动并读到旧项目 schema | fromVersion、toVersion、platform |

### 2.2 计算口径

- 安装成功率 = `install_succeeded` 的去重安装数 / `install_attempted` 的去重安装数。
- 首次激活率 = 安装后 7 天内至少一次 `plugin_context_read` 的去重安装数 / `install_succeeded` 的去重安装数。
- 首版回填成功率 = 首版 `version_submitted` 运行数 / 首版 `generation_started` 运行数。
- 返修回填成功率 = 返修 `version_submitted` 运行数 / 返修 `generation_started` 运行数。
- 批次通过率 = `batch_passed` 批次数 / 至少一次成功回填的批次数。
- 终版导出率 = `final_exported` 的去重安装数 / 至少通过一个批次的去重安装数。
- 升级成功率 = `upgrade_succeeded` 的去重安装数 / 发起升级的去重安装数。

数量和耗时优先分桶，不上传精确值。例如资产数分为 `0`、`1-5`、`6-10`、`11-14`；耗时分为 `<1m`、`1-3m`、`3-5m`、`5-10m`、`>10m`。

## 3. 严禁收集的内容

默认匿名观测不得包含：

- 项目名称、剧本、分镜脚本、提示词、台词、批注和返修意见。
- 人物、场景、道具图片，宫格图片，图片指纹或可逆缩略图。
- 资产文件名、完整本地路径、用户名、电脑名和 IP 地址。
- Codex 对话文本、任务标题、账号标识或模型输出正文。
- 批次令牌、runId、versionId、幂等键和原始操作日志。
- 可将多个产品或网站行为关联到同一自然人的广告标识。

错误只允许上传预定义 `errorCode`，不得把原始异常栈、请求体、日志行或文件路径直接发送到公网。

## 4. 匿名标识与保留

- 如 M2.1 确需去重，使用本地随机生成、仅属于本产品的安装标识，不读取设备序列号或账号。
- 安装标识应允许用户在设置中重置；卸载或“清除观测标识”后不能恢复关联。
- 事件服务端默认保留不超过 90 天；聚合指标可以保留更久，但不得反推单个安装。
- 原始失败事件访问权限最小化，导出、调试和公开看板只使用聚合数据。

## 5. 用户控制与离线边界

- M2.1 的匿名观测必须有清晰开关，默认策略在上线前单独评审；不得把开关藏在长协议中。
- 关闭观测后停止发送新事件，并允许删除仍可关联到本安装标识的服务端事件。
- 网络不可用、观测服务故障或用户关闭观测时，本地导入、批次、生成、返修、回填和导出必须继续工作。
- 版本检查与事件上报必须短超时、异步且不抢输入焦点，不得阻塞启动或生图主链路。

## 6. 数据共创是另一套授权

匿名产品观测不等于内容共创授权。M2.2 若需要剧本、批注、终稿或图片，必须：

1. 使用单独、明确、可撤回的授权，不与匿名观测捆绑。
2. 上传前逐项展示数据范围和用途，默认不勾选创作内容。
3. 提供本地预览、删除申请、授权记录和保留期限。
4. 明确是否用于人工评审、Skill 评测、模型训练或公开案例；用途变化需再次授权。

## 7. M2.1 开发前置闸门

开始 M2.1 前必须先确定：

- 事件字段白名单和错误码字典。
- 用户开关、撤回与删除流程。
- 接收服务、存储区域、保留时间与访问权限。
- 隐私说明文案和学员测试方案。
- 离线、超时和服务故障不影响本地核心闭环的自动测试。

以上未评审完成时，不应在 `v0.1.12` 中提前加入任何联网观测代码。
