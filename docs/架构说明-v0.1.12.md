# 分镜审核台 · 架构说明（v0.1.12）

> 本文记录已经交付的阶段稳定架构，不代表 M2.1 及以后规划已经实现。

## 1. 架构结论

`v0.1.12` 不是纯前端页面，也不是云端 SaaS。它由“浏览器页面 + 本机 Node.js 服务 + 本地文件数据 + Codex 个人插件”组成；业务服务只监听本机回环地址，剧本、资产和宫格版本默认不上传到开发者服务器。

```text
系统浏览器 / Codex 浏览器面板
        │ HTTP（127.0.0.1:43127）
        ▼
本机 Node.js 服务
  ├─ 页面与静态资源
  ├─ 项目 / 批次 / 运行 / 版本接口
  ├─ 图片校验与分类资产索引板
  ├─ 操作记录
  └─ 原子文件存储
        │
        ├─ data/project.json
        ├─ data/assets/
        ├─ data/reference-sheets/
        ├─ data/versions/
        └─ data/logs/storyboard-review.jsonl

Codex 本地工作任务
        │ MCP（stdio）
        ▼
分镜审核台个人插件
        │ HTTP（127.0.0.1:43127）
        └──────────────► 本机 Node.js 服务
```

Codex 的内置图片生成能力属于用户自己的 Codex 任务，不在本地服务中运行。本地服务负责准备冻结上下文、校验输入、接收生成结果并形成可审核版本。

## 2. 组件职责

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| 审核台页面 | 导入脚本、创建批次、选择资产、发起指令、审核与导出 | 直接调用图片 API、自动通过批次 |
| 本机 Node.js 服务 | 状态持久化、资产校验、索引板、运行令牌、版本回填、日志 | 账号、云同步、模型计费 |
| 个人插件 | 把 Codex 工具调用转发给本地服务 | 保存跨项目数据、替用户决定通过 |
| Codex 任务 | 按本批脚本和参考输入调用内置生图 | 修改其他批次、读取未选资产 |
| 本地文件目录 | 保存项目元数据和图片 | 多人并发、跨设备同步 |

## 3. 数据模型与持久化

当前状态文件 `data/project.json` 使用 `schemaVersion: 4`，核心实体为：

- `Project`：项目名、画幅、总镜头池、批次、资产和界面偏好。
- `Asset`：资产 ID、名称、人物/场景/道具类型、本地文件路径。
- `Batch`：源镜头快照、批次起点、资产选择、批注、状态和版本列表。
- `Run`：随机令牌、批次、模式、冻结脚本、资产输入、状态和幂等信息。
- `Version`：宫格图片、完整脚本文本、镜头结构、布局、来源运行和创建时间。

图片不以大段 DataURL 长期写入项目 JSON，而是分别落到资产、索引板和版本目录。状态写请求串行处理，并通过临时文件后原子替换正式文件；页面使用 revision 乐观并发控制，避免后台回填静默覆盖用户正在编辑的状态。

## 4. 本地 HTTP 接口

服务只监听 `127.0.0.1:43127`，主要接口如下：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/health` | 健康状态与产品版本 |
| `GET /api/bootstrap` | 读取完整本地项目状态 |
| `PUT /api/project` | 按 revision 保存页面状态 |
| `GET /api/export/final` | 汇总并必要时重编号终版脚本 |
| `POST /api/migrations/local-storage` | 空项目首次迁移旧浏览器数据 |
| `POST /api/batches/:id/runs` | 创建首版或返修运行 |
| `DELETE /api/batches/:id` | 删除最新批次及关联结果 |
| `POST /api/batches/:id/assets/validate` | 一次性校验本批全部资产 |
| `GET /api/runs/:id` | 页面轮询运行与回填状态 |
| `POST /api/mcp/context` | 按令牌读取冻结批次上下文 |
| `POST /api/mcp/status` | 回报生成阶段或失败原因 |
| `POST /api/mcp/revision-script` | 校验返修脚本并生成唯一生图脚本 |
| `POST /api/mcp/submit` | 提交新图片并创建不可变版本 |
| `GET /files/...` | 读取本地资产、索引板和版本图片 |

浏览器带 `Origin` 时只接受当前本机服务的 `127.0.0.1` 或 `localhost` 来源。运行令牌至少 16 位且只映射一次冻结运行；它不是互联网账号令牌，也不应对外分享。

## 5. MCP 工具边界

插件 `storyboard-review-desk@0.1.12` 提供五个工具：

1. `get_batch_context`：读取本次冻结镜头、画幅、返修意见和参考输入。
2. `get_batch_status`：读取运行状态和回填版本。
3. `report_generation_status`：回报准备、生成、提交或失败。
4. `prepare_revision_script`：把审核意见落实到完整脚本，并返回唯一允许用于生图的 `imageScript`。
5. `submit_storyboard_version`：提交新图、真实行列和幂等键，创建版本。

插件不开放自动通过、清空项目、删除批次或覆盖历史版本的工具。

## 6. 首版生成时序

```text
页面创建运行并冻结本批上下文
  → 用户新建本地 Codex 工作任务并粘贴指令
  → 插件按令牌读取上下文
  → 0～5 项资产直接作为参考；6～14 项使用 5 张分类索引板
  → Codex 原样使用 imageScript 调用内置生图
  → 插件提交本次新图片与真实宫格行列
  → 服务校验令牌、图片、脚本、容量、重复结果和幂等键
  → 图片复制到 data/versions/，批次追加不可变版本
  → 页面轮询发现 completed 并自动回填
```

不同批次要求新建不同 Codex 任务。隔离的技术核心是不同运行令牌和冻结上下文；新建任务同时降低 Codex 对话历史带来的参考污染。

## 7. 返修时序

```text
用户针对当前版本提交审核意见
  → 页面创建 revision 运行
  → Codex 先修改完整分镜脚本
  → prepare_revision_script 校验脚本确有变化并重新连续编号
  → Codex 只用返回的 imageScript 进行生图
  → submit_storyboard_version 回填新版脚本与新图片
```

审核意见只用于修改分镜脚本，不作为额外的正向、负向或检查提示词传给图片模型。

## 8. 安装与升级架构

- Windows 工具包自带 Windows Node.js 运行环境；macOS 通用包同时携带 arm64 和 x64 运行环境。
- 一键安装把个人插件复制到当前用户目录、登记个人市场并刷新 Codex 插件缓存。
- 一键启动先检查 `43127` 端口；已是当前版本则复用，旧版本占用则提示关闭旧服务。
- 工具包可以放在任意本地目录，但移动或改名后必须重新运行一键安装，使插件入口指向新位置。
- 覆盖升级不是在线自动更新：用户需保留或迁移旧 `data/`，运行新包的一键安装并重启 Codex。

## 9. 安全、隐私与外部依赖

- 服务仅绑定本机回环地址，不主动暴露到局域网或公网。
- `v0.1.12` 没有账号、云同步、匿名观测或开发者业务后端。
- Codex 只在用户发起任务后获得当前批次选择的文本与参考输入。
- 操作记录和备份可能包含创作信息，是否分享由用户决定。

当前页面通过 `https://cdn.tailwindcss.com` 加载 Tailwind 样式。这意味着干净电脑第一次完全离线打开时，核心服务与数据仍可工作，但页面样式可能不完整；已缓存也不构成可靠离线保证。此项作为 M2 发现记录，后续应改为随安装包内置的静态 CSS，再进行离线真机验收。

## 10. 当前非目标

- 账号、云数据库、跨设备同步和多人协作。
- 开发者代付或托管的图片模型 API。
- 公网控制台、匿名埋点、自动更新和教师审核。
- 多 Agent 适配、实时事件流或网页一键创建 Codex 任务。
- 为完成 M2 而重构已运行的业务代码。
